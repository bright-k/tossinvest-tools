# 설계 결정

ADR은 중요한 선택의 이유와 변경 조건을 보존합니다. 여기의 기본안은 다음 구현을 위한 기준이며, 별도 검증을 통과해야 하는 조건을 각 문서에 적습니다. 사용자가 후속 요구를 바꾸면 해당 결정을 대체합니다.

| 번호 | 결정 | 상태 |
|---|---|---|
| [0001](0001-runtime-and-structure.md) | Go 단일 서버와 원본 명세 기반 전체 지원 | 구현 기준안, P0 호환성 검증 필요 |
| [0002](0002-authorization-and-orders.md) | 서버 승인·정책·주문 기록과 실행 경계 | trading 전용 보안 기준안, readonly 선행 구현의 의존성이 아님 |
| [0003](0003-readonly-first.md) | readonly 우선 배포와 시작 프로필 | 사용자 후속 요구 반영 |
| [0004](0004-readonly-access-and-event-history.md) | 조회 계좌 선택·ID 확인·mock 인증·이벤트 보존 | 기본안 채택, 구현·수용 검증 미착수 |

새 ADR에는 제목, 날짜, 상태, 관련 요구사항, 맥락, 결정, 대안, 결과와 재검토 조건을 적습니다. 기존 문서의 과거 선택을 지우지 않고 새 ADR과 대체 관계를 연결합니다.
