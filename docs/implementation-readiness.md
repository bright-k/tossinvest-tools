# 구현 착수 검토

2026년 10월 26일 기준 문서는 P0부터 readonly R1·R2를 구현하기에 충분한 기반입니다. 실제 호환성·실행 가능성은 P0 결과로 확인해야 하며, 현재는 문서 정적 검증만 수행한 상태입니다. 선택적 trading은 전체 범위에 남겨 두되 초기 조회 배포의 의존성에서 분리합니다.

## 검토와 보완

| 발견한 문제 | 영향 | 반영한 해결 |
|---|---|---|
| readonly에서 도구를 숨기거나 거부하는 선택이 열려 있었음 | 구현자마다 tools/list와 직접 호출이 달라질 수 있음 | readonly에서 준비·실행·취소·정정·조건 변경 도구 미등록, 서비스·전송의 중복 방어를 계약으로 고정 |
| mock와 readonly/trading을 같은 모드 목록으로 사용했음 | 모의 거래 테스트와 실제 권한이 섞임 | mode와 backend를 분리하고 4개 조합을 검증 |
| 설정의 mode와 trading.enabled가 함께 있었음 | 설정 우선순위로 의도치 않게 거래 활성화 가능 | mode는 명시적인 프로세스 시작 옵션, 생략은 readonly. 일반 JSON의 권한 활성화 값 제거 |
| Keychain·설치 단계가 주문 구현보다 뒤였음 | 실사용 조회 서버가 주문 기능 완성을 기다리게 됨 | 실제 조회에 필요한 Keychain·접속 인증을 R1 앞으로, 조회용 서비스 운영을 P3에 배치 |
| P1에서 전체 주문 저널과 쓰기 검증을 선행 요구했음 | 초기 조회 완성 범위가 불필요하게 커짐 | R1·R2 최소 저장소 후 P4 additive migration으로 거래 상태 추가 |
| 과거 trading DB를 readonly에서 복구하는 의미가 없었음 | 자동 재시도가 조회 전용 실행에서 주문을 만들 수 있음 | readonly 복구는 조회만, 10분 유효 재시도도 실제 전송 금지 |
| 단일 준비 상태가 승인·WS와 결합돼 있었음 | readonly가 거래 기능 미준비 때문에 사용 불가해질 수 있음 | query·stream·trading 준비와 구현·활성 capability를 분리 |
| 초기 CLI·출력·접속 bootstrap이 미정이었음 | 조회용 CLI 전체 구현이나 임시 인증 우회로 범위가 흔들림 | 최소 CLI, helper, 경로·상태·오류 계약을 명시하고 업무 기능은 MCP 우선 |

## 지금 구현할 결과

- P0에서 공식 원본의 코드 생성·디코딩과 최소 MCP 호환을 검증합니다.
- P1·P2에서 키 없는 mock 실행과 사용자가 설정할 수 있는 실제 readonly 서버를 완성합니다. R1은 REST 조회 34개와 상태·진단·접속 인증입니다.
- P3에서 실시간 전체·복구·조회용 로컬 서비스를 더해 R2를 완성합니다.
- 소유자 승인·실주문 실행·한도·분리 계정의 선택은 P4의 T1에서 처리합니다. 미정이어도 R1·R2는 진행할 수 있습니다.

## 남은 검증과 결정

| 항목 | 해소 시점 | 조회 구현을 막는지 |
|---|---|---|
| 실제 OpenAPI 3.1과 생성기·공식 MCP SDK 호환 | P0 | P0에서 실증할 첫 작업 |
| Keychain 비밀 비노출 저장·helper·Codex 연결 | P1~P2 | 실제 readonly 배포 전 필요, mock 구현은 가능 |
| 독립 승인 인증·실주문 격리와 실제 한도 | P4, 실제 거래 활성화 전 | 막지 않음 |
| 실제 계좌·데이터 처리 범위·토스 이용 조건 | 사용자의 실제 연결 시 | 모의 구현을 막지 않음 |
| 라이선스와 제3자 명세 포함 공개 배포 조건 | 공개 릴리스 전 | 구현을 막지 않음 |

문서가 충분하다는 판단은 모든 결정을 미리 끝냈다는 뜻이 아닙니다. 첫 개발 작업과 뒤로 미룰 결정을 분리했고, 프로필·등록·복구의 큰 경계를 정한 상태입니다. 후속 검토의 네 계약은 아래 기본안으로 문서화했으며 실제 구현·검증 증거는 계속 추가합니다.

## 2026년 10월 26일 후속 검토

판정은 **P0 착수 가능, R1·R2의 네 보완 계약은 기본안 채택 완료, 구현·수용 검증 미착수**입니다. 최초 검토에서는 아래 네 항목을 미해결로 발견했고, 이후 사용자의 기본안 반영 요청으로 [ADR 0004](decisions/0004-readonly-access-and-event-history.md)와 관련 문서에 결정을 반영했습니다. 문서의 결정을 구현 완료로 처리하지 않습니다.

| 항목 | 검토 당시 문제 | 채택한 계약과 구현 시점 |
|---|---|---|
| R1: 계좌 허용·접속 주체 bootstrap | 계좌 선택·별칭·접속 권한 연결 절차가 없었음 | [계좌 계약](interfaces.md#계좌-선택과-접속-권한): 기본 허용 집합은 비어 있고 setup accounts가 동일 UID 소유자 소켓으로 서버의 발견·grant를 처리. 마스킹 응답과 access_revision 철회 검사. P1~P2, T-039~T-040 |
| R1: 처음 보는 주문 ID | 사전 거부 문구가 앱 신규·종료 주문 조회와 충돌했음 | [ID 계약](interfaces.md#주문-id와-계좌-소유-관계): 미허용 계좌·확인된 타 계좌는 사전 거부. unknown은 명시한 허용 계좌의 단건 GET으로만 확인하고 fallback 금지. R-006 조정. P1~P2, T-041 |
| R1: mock의 로컬 접속 인증 | Keychain 비사용과 MCP credential 준비의 관계가 미정이었음 | [mock 계약](interfaces.md#mock-접속-credential): 실제 SecretStore와 접속 provider를 분리. 실행별 난수 credential·mock 전용 0600 파일·backend/run_id 검사와 재시작 회전. P1~P2, T-042 |
| R2: 이벤트 보존·커서·큐 | 보존·만료·포화의 실패 의미가 없었음 | [보존 계약](architecture.md#이벤트-보존과-수신-큐)과 [커서 계약](interfaces.md#주문-이벤트-페이지와-커서): 7일/계좌당 100,000건/전체 256 MiB, 큐 1,024건/8 MiB/1초, CURSOR_EXPIRED와 gap 복구. P3, T-043~T-044 |

정확한 Go·SDK·생성기 버전, 생성 타입의 미지 필드 보존, HTTP timeout·호출 제한 기본값, DB schema와 오류 JSON의 세부 형식은 해당 구현 단계에서 정하고 테스트로 고정할 수 있습니다. 특히 operations의 `group`은 문서상 업무 분류이므로 호출 제한 그룹으로 그대로 사용하지 않고 원본 작업 설명의 Rate Limits Group과 대조해야 합니다. 주문 승인·격리·실거래 한도는 예정대로 P4와 실제 거래 활성화 전 결정할 항목입니다.

### 최초 검토의 검증 범위

- 검토 시작 시 로컬 JSON 4개와 Markdown 21개를 읽고 상대 링크 62개·코드 fence를 검사했다. 검토 기록 추가 뒤 상대 링크 67개·코드 fence·JSON 구문을 다시 확인했다.
- 원본 2개의 SHA-256·바이트 수·문서/API 버전과 내부 참조 431개가 일치했다.
- REST 41개 작업의 method/path/operationId·path/query 입력·서버 관리 계좌 헤더·본문 유무·프로필 분류, WS 10개 작업의 방향·채널 대응을 확인했다.
- 계획 도구 집합은 R1 readonly 35개, R2 readonly 39개, T1 trading 47개이며 중복이 없었다. 모든 대응 상태는 planned이고 검증 증거는 비어 있다.
- 요구사항 37개가 수용 검증 38개에 참조되어 있다. 이는 추적 관계 확인이며 실제 수용 검증 통과를 뜻하지 않는다.
- [공식 Codex MCP 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)에서 로컬 HTTP용 `http_headers_helper`와 JSON 헤더 출력 지원을 확인했다. 이 저장소의 helper·현재 클라이언트와의 실제 연결은 아직 검증하지 않았다.
- [Go 공식 릴리스](https://go.dev/doc/devel/release)와 [oapi-codegen v2.8.0 릴리스](https://github.com/oapi-codegen/oapi-codegen/releases/tag/v2.8.0)에서 문서의 후보 계열과 OpenAPI 3.1 초기 지원 근거를 확인했다. 의존성 호환 판정은 P0에 남긴다.

검사는 임시 Python 표준 라이브러리 스크립트로 수행했으며 저장소 자동 검사 명령은 아직 없다. `command -v go`로 Go가 현재 PATH에 없음을 확인했다. Go 모듈·애플리케이션 소스가 없어 코드 생성·컴파일·애플리케이션 테스트는 실행하지 않았다. 토스 overview/FAQ는 이번 웹 도구에서 본문을 가져오지 못했으므로 재검증 근거에 포함하지 않았다. 고정 원본은 변경하지 않았다.

### 기본안 반영 후 검증

문서 22개·상대 링크와 anchor 102개·JSON 4개를 검사했다. 원본 해시·내부 ref 431개, REST 41개·WS 10개·35/39/47개 계획 도구 집합은 그대로 일치한다. contract_reference 17개가 실제 문서 절을 가리키고, 요구사항 37개에 대한 수용 시나리오 44개의 ID·참조를 확인했다. 새 여섯 시나리오는 계획 상태이며 코드 생성·컴파일·애플리케이션 테스트·실제 계좌 제한 검증은 실행하지 않았다.
