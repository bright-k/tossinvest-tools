# 요구사항

`tossinvest-tools`는 본인 토스증권 계좌를 도구로 관리하기 위한 서버와 CLI를 제공합니다. 공식 API 전체를 지원하면서 토스 인증정보와 주문 권한을 서버에서 통제합니다. 이 문서의 기준일은 2026년 10월 26일입니다.

## 사용자 요구와 설계 기준

사용자가 요청한 범위는 저장소 이름 `tossinvest-tools`, 서버의 MCP 지원, CLI 제공, 로컬 PC 우선 실행, 공식 Open API의 전체 기능 지원, AI에 토스 키를 직접 제공하지 않는 구조, 그리고 후속 구현·변경을 위한 문서 기반입니다. 추가로 실제 주문 명령은 서버 시작 시 선택적으로 포함하고, 우선 readonly로 주로 사용합니다.

Go, SQLite, 단일 프로세스, 기본 포트와 세부 도구 이름은 다음 구현을 위한 설계 기준안입니다. Go SDK·생성기 호환성을 검증한 뒤 버전을 고정하며, 대안과 변경 이유는 ADR로 남깁니다. 실제 주문 한도·허용 계좌·승인 인증 방법은 소유자가 결정할 운영 설정입니다.

| R-002 | 공식 실시간 전체를 지원한다 | KR·US 체결·호가, 본인 주문 이벤트, 선언·ack·error·PING·pong과 재연결을 검증한다 |
| R-003 | 서버가 MCP를 직접 제공한다 | 독립 실행한 서버의 `/mcp`에 클라이언트가 연결해 발견·호출·오류 처리를 수행한다 |
| R-004 | 서버와 CLI는 공통 코어를 사용한다 | CLI 업무 기능이 실행 중인 서버를 거치며 우회 주문 경로가 없다 |

| R-007 | 모든 조회 조건을 지원한다 | 원본에 정의된 필터·기간·커서·수량·시장 등 유효한 입력 조합을 누락하지 않는다 |
| R-008 | 일반 주문의 전체 기능을 지원한다 | 지정가·시장가·지원 TIF, 수량·금액 방식, 정정·취소와 시장별 제한을 검증한다 |
| R-009 | 조건주문의 전체 기능을 지원한다 | SINGLE·OCO·OTO의 등록·조회·수정·취소와 타입별 제약, 변경 후 ID 추적을 검증한다 |
| R-010 | 주문 정보를 사전 검증한다 | 최신 매수 가능 금액·매도 가능 수량·미체결·가격·장 운영·유의사항과 정책을 검사한다 |
| R-011 | 쓰기 작업을 사용자 승인에 묶는다 | 생성·정정·취소·조건주문 변경 각각의 정확한 초안에 유효한 사용자 승인 증거가 필요하다 |
| R-012 | 중복 제출과 미확정 결과를 관리한다 | 전송 전 기록, 원래 멱등키·본문 유지, 시간 경계와 재시작 복구를 검증한다 |
| R-013 | 주문 상태를 독립적으로 추적한다 | 접수·부분 체결·전량 체결·취소 대기·정정 대기·종료와 제출 결과 미확정을 구분한다 |
| R-014 | 앱·WTS에서 생긴 변경도 반영한다 | 공식 API로 조회되는 외부 채널 주문·보유 자산 변화를 동기화하고, 서버 작성 주문과 구분한다 |
| R-015 | 중단과 재개를 명시한다 | 신규 쓰기 중단, 미체결 취소, 조건주문 취소, 포지션 청산을 서로 다른 작업으로 다룬다 |
| R-016 | 로컬 실행을 제공한다 | `setup`, `setup accounts`, `serve`, `doctor`, 사용자 서비스 관리와 계좌 목록·보유 자산·현재가 CLI 조회의 계약을 구현한다. 계좌 선택은 실행 서버의 소유자 소켓을 거치고 비밀 입력·진단 출력을 분리한다 |

| R-031 | 의존성을 재현 가능하게 고정한다 | 생성기·모듈 버전과 합계가 고정되고 자동 업그레이드가 운영 실행에 섞이지 않는다 |

| R-035 | 조회 전용을 먼저 배포한다 | P0~P2의 R1과 P3의 R2는 주문 승인·격리·주문 저널 구현 없이 사용할 수 있다 |
| R-036 | 실제 활성 기능과 준비 상태를 표시한다 | mode/backend·query/stream/trading 준비를 구분한다. readonly에서 trading_ready=false는 정상이며 등록 capability를 확인할 수 있다 |
| R-037 | readonly 복구와 서비스 재시작이 쓰기를 만들지 않는다 | 과거 trading DB의 재전송도 차단한다. 기본 서비스 설치는 readonly를 argv에 고정하고 기존 거래 설정을 암묵적으로 상속하지 않는다 |

## 전체 지원의 범위

공식 공개 명세에 있는 기능을 대상으로 합니다. 전체 지원은 모든 계좌·종목·세션에서 주문이 항상 허용된다는 뜻이 아닙니다. 거래 자격, 시장 운영, 잔고와 토스의 제한은 그대로 적용합니다. 서명·토큰·계좌 헤더·고액 확인 등 서버 책임 필드는 기능을 유지하면서 도구의 임의 입력에서 분리합니다.

토스 원본 클라이언트 전체 구현과 운용 권한 활성화는 별개입니다. 먼저 R1 REST 조회와 R2 실시간 조회를 제공하고, 선택적 T1에서 전체 쓰기를 완성합니다. 조회 릴리스의 완료는 정당한 중간 결과이며 전체 API 완료와 구분합니다. 프로필과 등록 계약은 [실행 프로필](runtime-profiles.md)을 따릅니다.

초기 CLI의 필수 범위는 setup·serve·doctor·status·접속 helper·service 관리입니다. 원본 34개 조회 기능의 필수 업무 접속은 MCP입니다. 개별 조회·매매용 CLI 하위 명령은 후속 확장으로 두며, 추가하면 같은 서버를 거칩니다.

조회용 계좌 bootstrap·권한과 ID 확인·mock 접속 인증·이벤트 보존의 기본안은 [접속 계약](interfaces.md)과 [ADR 0004](decisions/0004-readonly-access-and-event-history.md)를 따릅니다. R-006의 사전 거부는 미허용 계좌와 이미 확인된 타 계좌 ID에 적용하며, 미확인 ID 전체를 차단하는 의미로 확대하지 않습니다. 이것은 앱에서 새로 생성된 주문의 조회를 보존하기 위한 계약입니다.

## 초기 범위 밖

- 타인 계좌를 맡아 운영하는 다중 고객 서비스와 상업적 데이터 재배포.
- 비공식 WTS 기능·쿠키·브라우저 자동화로 공식 API의 빈 기능을 보충하는 일.
- 출금·송금·자동환전 기능을 새로 가정하거나 구현하는 일.
- 모델이 사용자 승인 없이 자율적으로 매매하는 전략 엔진.
- 백테스트·리서치·차트 플랫폼, 복수 증권사 추상화, 모바일 앱.
- 기본 실행을 위한 Docker·Kubernetes·Redis·외부 DB·LLM API 의존성.

범위 밖 기능도 후속 사용자 요청으로 변경할 수 있습니다. 변경 이유·영향·검증 조건을 먼저 관련 문서에 반영합니다.

## readonly R2 구현 판정 — 2026-10-26

이번 사용자 요청에 따라 P0~P3의 조회 범위를 구현했다. 초기 실행 파일 0.2.0은 toss/mock의 trading 시작을 모두 CAPABILITY_UNAVAILABLE로 거부한다. R-033/R-034의 trading 지원과 주문 관련 R-008~R-015·R-019 등 전체 쓰기 검증은 T1의 후속 목표로 남는다. 조회·실시간 관련 현재 근거와 사용자 설정 대기는 [검증 기록](verification/README.md)에 연결한다. 미정인 주문 승인·격리·저널을 readonly의 선행 조건으로 확대하지 않았다.

원본 예제 호환 처리, 오류 hint의 credential 필터, 동적 호출 제한, 실제 Codex 검증 범위는 [adapter 기록](adapter-notes.md)과 [로컬 운영](local-operation.md)을 따른다. 구현·모의 검증의 완료와 사용자 Codex 등록/이 채팅 재연결·실계좌 검증은 별도로 판정한다.

## CLI 업무 조회 확장 — 2026-10-26

사용자 요청으로 `accounts`, `holdings --account-alias=... [--symbol=...]`, `prices --symbols=...`를 추가한다. 기존 서버의 MCP 접속 인증·scope·계좌 grant·철회를 그대로 사용하며 CLI의 Toss 직접 접속/자동 계좌 선택은 금지한다. 성공 JSON의 data/meta·Decimal 문자열과 서버 오류 code/exit code를 보존한다. 실제 키·계좌 없이 mock 및 빌드한 CLI 프로세스로 검증하며 결과는 [CLI 조회 검증](verification/cli-queries.md)에 남긴다. 다른 31개 조회의 CLI 구현이나 주문은 이번 확장 범위가 아니다.
